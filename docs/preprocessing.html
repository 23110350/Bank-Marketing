Data Preprocessing

Cleaning, transforming, and balancing data before modeling

📌 Why Preprocessing?

Raw data is never ready for machine learning

Raw data contains noise, inconsistencies, and imbalances that can mislead machine learning models. Preprocessing transforms raw data into a clean, structured format that maximizes model performance.

In this project, preprocessing involved 9 key steps: from handling missing values all the way to balancing the dataset using class weighting in the updated experiment.

Class Imbalance Handling in the Updated Experiment

Training-only class weighting instead of synthetic oversampling after one-hot encoding

Important methodology update: The corrected experiment does not use the original SMOTE-after-one-hot-encoding workflow. It uses class weighting where supported, with preprocessing fitted within each training fold. This avoids creating fractional one-hot category indicators through synthetic interpolation.

Preserving previous-contact information

The original value pdays = -1 indicates that the customer was not previously contacted. The updated pipeline preserves this distinction and adds a previous-contact indicator rather than converting -1 to zero, which would incorrectly imply a contact exactly zero days ago.

Training-only preprocessing

Numeric imputation/scaling and categorical encoding are fitted inside the training pipeline. During cross-validation, each fold learns its own preprocessing from that fold's training partition. The held-out test set is not used to fit transformations or select models.

💡 Key Preprocessing Insights

Important concepts and best practices

⚠️

Data Leakage Prevention

The updated pipeline fits preprocessing within training folds and keeps the final test set separate. This ensures test data remains completely unseen during preprocessing, providing true performance estimates.

🔄

Why class weighting?

The updated experiment uses class weighting where supported rather than generating synthetic observations after one-hot encoding. The held-out test set retains its original class distribution.

🏆

StandardScaler Order Matters

Fit the scaler on training data only, then use those statistics to transform test data. This prevents test set statistics from influencing the training process.

❌

Why Remove Duration?

Call duration is only known AFTER the call completes. In production, we cannot use this to predict subscription. Removing it ensures our model is deployable in real-world scenarios and prevents data leakage.
