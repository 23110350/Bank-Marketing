# Bank Marketing Subscription Prediction — ES 335

An individual ES 335 course project investigating whether customer and campaign information available before a marketing call can help predict term-deposit subscription.

## Research question

How effectively can classification models predict whether a customer will subscribe to a term deposit using information available before a marketing call, and how do classification thresholds affect the precision–recall trade-off?

## Dataset

The project uses the UCI Bank Marketing `bank-full.csv` dataset (45,211 observations). Each row represents a customer contact/marketing observation. The target `y` indicates whether the customer subscribed to a term deposit.

Source: https://archive.ics.uci.edu/dataset/222/bank+marketing

The feature `duration` is excluded because call duration is only known after a call ends and is unavailable for a pre-contact targeting decision. The `pdays = -1` value is preserved as a distinct no-previous-contact condition, with a separate previous-contact indicator.

## Current experiment

The corrected comparison is generated by `analysis/reproduce_analysis.py`. It uses:
- a stratified 80:20 train/test split;
- 3-fold stratified cross-validation on the training partition;
- preprocessing fitted inside scikit-learn pipelines, including within cross-validation folds;
- a majority-class dummy baseline;
- Logistic Regression, Decision Tree, Random Forest, and XGBoost candidates;
- class weighting where supported, rather than SMOTE applied after one-hot encoding;
- a final held-out test set that is not used for model selection.

The reported test metrics are in `outputs/model_comparison.csv`. Held-out predictions used by the static threshold explorer are in `website/data/test_predictions.json`. The threshold explorer recalculates metrics from those stored predictions in the browser; it does not train models in the browser.

### Current held-out comparison

| Model | Accuracy | Balanced accuracy | Subscriber precision | Subscriber recall | Subscriber F1 | ROC-AUC |
|---|---:|---:|---:|---:|---:|---:|
| Majority baseline | 0.8830 | 0.5000 | 0.0000 | 0.0000 | 0.0000 | 0.5000 |
| Logistic Regression | 0.7553 | 0.6983 | 0.2667 | 0.6238 | 0.3736 | 0.7722 |
| Decision Tree | 0.7364 | 0.6666 | 0.2394 | 0.5756 | 0.3381 | 0.7175 |
| Random Forest | 0.8251 | 0.7300 | 0.3549 | 0.6059 | 0.4476 | 0.7976 |
| XGBoost | 0.8940 | 0.5730 | 0.7181 | 0.1541 | 0.2537 | 0.7807 |

Accuracy alone is not sufficient for this imbalanced dataset: the majority baseline obtains 88.30% accuracy while detecting no subscribers. Random Forest has the highest positive-class F1 among the candidate models in this particular experiment. XGBoost has the highest accuracy but substantially lower subscriber recall at the default threshold. These are dataset-specific predictive results, not causal or clinical claims.

## Reproduction

From the repository root:

1. Install Python 3.10 or later.
2. Create and activate a virtual environment.
3. Install dependencies: `python -m pip install -r requirements.txt`.
4. Ensure `data/bank-full.csv` is present. If obtaining it separately, download it from the UCI source above and retain the expected filename.
5. Run: `python analysis/reproduce_analysis.py`.
6. Review `outputs/model_comparison.csv` and the generated predictions.
7. Open `website/index.html` locally, or publish the `website/` directory using GitHub Pages.

The primary `Reproduce_Experiment.ipynb` calls the corrected experiment script and displays the generated comparison. The six original notebooks are retained as reference materials; their earlier preprocessing and saved model outputs are not the source of the current website's reported comparison.
